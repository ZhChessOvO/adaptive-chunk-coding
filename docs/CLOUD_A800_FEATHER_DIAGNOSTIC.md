# A800 单卡 Generate 羽化诊断

## 结论

在冻结 v5 的 37 条 REDS+UVG 输出上，16 像素是 8／16／32 三个候选里最合适的折中：

- 有 Generate 边界的 33/33 条样本，16 像素都降低了边界梯度误差；
- UVG 平均 LPIPS 相比 8 像素降低 0.000866；
- 合并 37 条 LPIPS 比 8 像素高 0.001702，明显小于 32 像素的 0.005303 代价；
- 因此 v6 默认使用 16 像素，但不把它当成硬门槛。

更宽羽化只解决“怎样贴回去”，不能解决“这个区域本来是否应该 Generate”。Jockey 的
平滑背景误生成仍然存在，所以 v6 还需要空间一致性和 UVG 跨域适配。

## 实验怎样做

- 复用联合评估已经保存的 spatial-QP fresh decode 和 SeedVR2 ROI；
- 不重新运行 codec 或 SeedVR2，不改变 4×4 动作图；
- 重新组合 8、16、32 像素羽化输出；
- 8 像素必须与冻结 v5 正式输出逐像素一致；
- 同时计算整段 LPIPS、PSNR、时序差和固定 48 像素边界带内的梯度／RGB 误差。

## 固定图检查

人工检查 Beauty、Jockey、YachtRide 的第 9 帧：

- Beauty 和 YachtRide 从 8 到 16 像素时，动作交界更柔和；
- 32 像素继续变柔和，但更多 Generate 内部区域被 Base 重建替代；
- Jockey 的草地／背景仍被 Generate 过度平滑，说明主要问题是误选而不是羽化宽度；
- 未发现错位、空块、越界或动作图变化。
