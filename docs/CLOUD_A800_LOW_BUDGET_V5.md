# A800 单卡低预算保守纠错与联合评估（v5）

## 这一轮解决什么问题

v4 证明了两件事：同画面上下文（v2）和临时 Base 编解码损伤（v3）都含有有用信息；
但让一个融合模型完整改写 v1 后，训练折外数字变好，六条完整开发视频却略微变差。

v5 因此不再问“怎样做一个更强的新控制器”，而是问：**什么时候有足够证据，只对稳定的
v1 做一个小纠正？**

最简单地说：

- v1 给默认答案；
- v2 独立判断一个区域相对整帧和邻居是否特殊；
- v3 独立判断 codec 实际把这个区域压坏了多少；
- 只有 v2、v3 对纠错方向一致，而且各自三个小模型的分歧不大时，v5 才纠错；
- 两个专家给出的幅度不同时，只采用较小的可信幅度，否则保持 v1。

这不是“实验改善多少才允许继续”的硬门槛，而是部署控制器内部的逐区域保守规则。

## 训练选择

选择阶段只复用 v4 已保存的 REDS train 分组折外预测，不重新读取 validation。对 Generate
utility、Enhance 收益和 Enhance 字节成本三项目标分别做下面的计算：

```text
上下文可信幅度 = max(|上下文纠错| - z × 上下文模型分歧, 0)
Base-probe 可信幅度 = max(|Base-probe 纠错| - z × Base-probe 模型分歧, 0)

若两者同号且可信幅度都大于 0：
    最终纠错 = 较小的可信幅度 × 共同方向 × 纠错比例
否则：
    最终纠错 = 0，也就是保留 v1
```

只比较一组很小、容易解释的设置：

- 不确定性系数 `z ∈ {0, 0.25, 0.5, 1, 1.5, 2}`；
- 纠错比例 `{0.25, 0.5, 0.75, 1}`；
- 原样 v1 也参加同一排序。

选择顺序仍是平均 oracle regret、最差四分之一 utility、有害 Generate 比例；仍相同时优先
实际纠错更小的版本。没有单独的通过／失败数字。选择结束后才在完整 train 上分别训练
上下文和 Base-probe 两组三成员小模型，并只让一个最终候选进入开发闭环。

## 开发与论文评估

- REDS `val/000..005` 是开发集，允许用来在 v1 与冻结 v5 之间作最终开发选择；
- REDS `val/006..023` 已影响历史实验，可作复现、误差分析和论文汇总，但不再称新的独立测试；
- REDS `val/024..029` 是新评估候选；运行前固定代码、checkpoint、前 17 帧与 512×512 裁剪；
- UVG、QST 等外部视频与 REDS validation 放入同一个跨分布论文评估池，同时报告每个
  数据集和合并统计，不单列成“应用测试”；
- 任何评估结果一旦用于改变方法或设置，对应样本立即改记为开发用途。

本轮首先完成六条既有开发视频的真实闭环。如果 v5 综合上仍不如 v1，就诚实保留 v1 为
主版本；v5 仍作为有解释力的消融进入论文记录。之后冻结最终版本，再做扩展评估。

## 2026-09-18 v5 开发闭环结果

训练阶段比较了 225 个候选，完全不读取 validation。最终自动选择
`z=0.25`、纠错比例 `1.0` 的 context-probe 共识版本：训练集分组折外的平均 oracle
regret 从 v1 的 `0.113505` 降到 `0.103148`，有害 Generate 比例从 `11.10%` 降到
`10.12%`。完整 train 上的两组三成员专家训练约 93.8 秒，checkpoint 为 251,374 B。

冻结后在 REDS `val/000..005` 跑了六条真实闭环，结果如下。所有字节来自最终
spatial-QP 文件；LPIPS 越低越好。

| 方法 | 平均字节/17帧 | LPIPS | 平均完整秒 |
|---|---:|---:|---:|
| v1 低预算 | 10497.5 | 0.463212 | 21.591 |
| v5 保守共识 | 10429.5 | 0.461972 | 22.566 |
| v5 关闭 Generate | 11930.5 | 0.485262 | 6.232 |
| v5 关闭 Enhance | 6726.3 | 0.510746 | 21.771 |
| 全 Generate | 4786.8 | 0.478122 | 28.248 |

- v5 相对 v1 平均少 68 B、LPIPS 低 `0.001240`，但逐视频只有 3/6 更好；应解释为
  小幅平均改善，而不是每条视频都更稳定；
- 相对逐样本最近均匀 QP，v5 平均改善 `0.070152` LPIPS，6/6 方向一致；
- 关闭 Generate／Enhance 后分别平均变差 `0.023291`／`0.048774`，均为 6/6；
- 96 个区域为 Base 26、Generate 24、Enhance 46；v2/v3 共识实际激活 152 个逐目标纠错；
- 18 个新 spatial-QP 流全部通过真实文件字节复核和逐像素 fresh decode；六张固定第 9 帧
  图均生成，已人工检查首、中、末三张，没有发现错位、空块或明显拼接错误；
- 正式闭环约 901 秒，峰值 `nvidia-smi` 显存 22097 MiB，输出约 294.3 MB。

在“不设硬门槛、直接选综合上更合适版本”的口径下，下一步冻结 v5 进入联合评估。原因是
它在平均画质和真实字节上同时略优于 v1，同时保留了 v2 的上下文含义与 v3 的真实 codec
损伤证据。3/6 的逐视频结果也意味着扩展评估必须如实报告稳定性，联合评估结果不得再反过来
改 controller 或设置。

联合评估固定 REDS validation 30 条和 UVG 标准 7 条，每条前 17 帧、512×512；同时报告
REDS、UVG 和合并统计，并保留每条样本的历史角色。QST 不用含糊的旧 `sky` 别名替代：在
取得官方整库或可登记的官方 clip ID 前，账本会明确写成“暂未纳入”，而不是静默换数据。
