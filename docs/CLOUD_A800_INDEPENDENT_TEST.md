# A800 单卡一次性独立测试协议

## 授权与目的

用户在 2026-09-18 明确授权读取此前未使用的 REDS `val/012..023`。这 12 条视频只用于
一次性独立测试：验证已经冻结的控制器、低／中预算点和常驻 ROI 执行能否从开发集
`val/000..005` 泛化。看到测试结果后不再用这 12 条视频调参数、改 checkpoint 或重新
选择预算点。

`val/024..029` 继续封存，不能读取。DCVC-UF、SeedVR2 和 5768 参数控制器都保持冻结；
不生成新 teacher 标签，不重新训练，也不进入多卡或模型／codec 微调。

正式输出固定写到：

```text
/root/autodl-fs/DCVC/runs/a800_independent_test_20260918
```

## 在读取图片前固定的样本

- 测试序列：`012..023`，每条恰好取一个样本，共 12 个；
- 每条使用第 0–16 帧，共 17 帧；
- 使用与开发集相同的 512×512 中心对齐裁剪：`x=384, y=96`；
- 固定第 9 帧做可视化；
- 按序列号从小到大运行；随机种子固定为 `20260917 + 2000000 + 序列号`；
- 不根据视频内容筛样本、换裁剪、换帧窗或排除困难样本。

## 冻结的方法和对照

控制器 checkpoint 固定为第一轮单卡试跑保存的
`a800_pilot_20260917/pilot/controller/controller.pt`。求解器参数保持不变：Enhance
fallback 字节比例为 `0.25 / 0.50 / 1.00`，Generate tile 上限为 `4 / 8 / 12`。

本次只正式检验已经在开发阶段声明的两个点：

- 低预算：`mlp-budget-0`；
- 中预算：`mlp-budget-1`。

每条测试视频固定报告：

1. 均匀 QP8／16／24／32；
2. 相同四个 QP 的 BasicVSR++ 确定性对照；
3. 全 Generate 和 Enhance-only；
4. 低预算联合路由、同路由关闭 Generate、同路由关闭 Enhance；
5. 中预算联合路由、同路由关闭 Generate、同路由关闭 Enhance。

所有空间流按真实落盘字节计费，包含头部、action map 和全部子流。每条流必须在独立
进程 fresh decode，且与编码端重建逐像素一致。Generate 路径采用常驻 ROI：同一个
样本、同一个路由只加载一次 SeedVR2。正式时间包含 fresh decode、模型进程加载、ROI
恢复和拼接；正式运行前只用已消费的开发样本做一次不计入结果的文件缓存预热。

## 预先固定的报告和判断

LPIPS 是主要质量指标；同时报告 PSNR、时序误差、真实字节、完整解码时间和峰值显存。
低／中预算分别与每条视频字节最接近的**已测离散均匀 QP 点**比较，不把它写成严格
同码率插值。

对低预算和中预算分别报告以下数字：

- 联合路由相对最近均匀 QP 的逐样本 LPIPS 差值、12 条均值和改善条数；
- 联合路由相对全 Generate 的质量、字节和时间，但明确这不是同码率比较；
- 关闭 Generate／Enhance 后的 LPIPS 差值和变差条数；
- Base／Generate／Enhance 动作总数；
- 完整时间是否低于全 Generate。

预先固定的“独立测试支持开发结论”标准为：

1. 联合路由相对最近均匀 QP 的平均 LPIPS 更低，并且至少 8/12 条更低；
2. 关闭 Generate 和关闭 Enhance 的平均 LPIPS 都变差，并且各至少 8/12 条变差；
3. 联合路由的平均完整时间低于全 Generate，并且至少 8/12 条更快；
4. 所有真实流的 fresh decode 均逐像素一致。

低预算和中预算各自独立判定。全 Generate 比较、PSNR、时序和动作比例无论正负都完整
报告，不作为事后改规则的理由。若任何判据失败，保留负结果并停止，不回到这 12 条
视频继续调参。

## 工程边界

- 长任务在 tmux 中运行，每分钟记录进度、GPU 和三块盘；
- 样本和阶段使用原子完成标志，可在服务器重启后从完整样本继续；
- 中断在 ROI batch 内时整批小任务重跑，不能只补剩余组件并低估时间；
- 文件存储或数据盘达到 80% 时停止新样本；
- 测试数据、码流、PNG、日志和正式结果不进入 Git，也不记录文件哈希；
- 结果完成后更新 README、云端文档和 Notion，再单独提交结果代码与文档。
