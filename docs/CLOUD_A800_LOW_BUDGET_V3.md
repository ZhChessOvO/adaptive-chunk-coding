# A800 单卡低预算稳定性改进（v3：编码端 Base 预分析）

## 假设与 v2 的区别

v2 已证明，只在原始 RGB 统计之间加入相对位置和邻域关系，无法显著降低折外动作遗憾。
本轮改为一个更直接、仍可实际部署的信号：编码器先用统一 Base（QP16）做一次很快的
临时编码和本地解码，再比较“待编码原视频”和“Base 重建”在每个区域的失真。失真大的
区域更可能需要 Generate 或 Enhance，模型不必只凭纹理统计猜测 codec 会在哪里失败。

这不是 decoder 偷看 GT。真实编码器本来就拥有未压缩输入，视频编码中的两遍分析也很
常见；临时 QP16 码流只在编码端使用并丢弃，不传给 decoder。代价是额外编码计算，因此
必须把预分析的编码、解码和特征计算时间单独报告，不能藏在推理时间之外。

## 数据边界

- 训练和选型仍只使用 REDS train `000..239` 的既有 500 个 teacher 样本；
- Base 预分析训练特征来自这些 teacher 文件里已经保存的 Base 区域指标，不生成新
  SeedVR2 标签；
- 5 折仍固定为 `int(sequence) % 5`，同一原视频不会跨训练折和验证折；
- 只有训练集门槛通过后，才可在既有 `val/000..005` 上做一次冻结验证；
- 已消费的 `val/012..023` 不参与任何选择或诊断；`val/024..029` 继续不读取；
- 新独立测试仍必须另行预注册并取得用户授权。

## 冻结的特征、目标和模型

比较两个候选，二者使用相同训练日程和直接目标：

1. `raw-direct`：现有 16 个编码端 RGB／运动特征；
2. `base-probe-direct`：在上述 16 维之外，加入每个区域的 Base LPIPS、PSNR、RGB MSE、
   时序差值，以及这 4 项相对当前 4×4 区域均值的差和 z-score，共 28 维。

模型不再同时拟合 8 个间接量，而直接拟合预算求解器真正使用的 3 项：

- Generate utility：LPIPS 收益减时序风险、PSNR 风险和实测 ROI 时间代价；
- Enhance LPIPS 收益；
- Enhance fallback 字节成本。

三项各用一座独立的两层、宽 32 的小 MLP，避免容易预测的字节／时序目标通过共享 trunk
干扰最难的 Generate 排序。每折仍固定训练 3 个 seed、240 epoch，部署取 ensemble 均值。
两种收益只测试折外 RMSE 系数 `{0, 0.25, 0.5}` 的保守扣减，共 9 种固定组合。低预算、
Generate 上限、fragment guard 和动作语义都不变。

## 训练集门槛

候选仍先对 500 个样本生成严格折外预测，再以真实 fallback 成本相同的 oracle 计算动作
regret。每种特征的 9 个校准组合按以下固定顺序选择：

1. 平均 oracle regret 最低；
2. 相差不超过 `1e-6` 时，最坏 25% 样本平均 utility 更高；
3. 再相同则保守系数更小。

只有最佳 `base-probe-direct` 相对最佳 `raw-direct` 把平均 regret 降低至少 10%，并且最坏
25% utility 不降低，才训练全量 ensemble、生成开发路由。否则记录第二个训练集内负结果
并停止，不用开发数据试错。

## 部署和一次性开发验证

实际编码顺序固定为：

```text
原视频
  -> 临时统一 QP16 encode + 本地 decode
  -> 计算 16 区域 Base 失真
  -> 小控制器 + 预算求解器得到 B/G/E 动作图
  -> 正式一次 spatial-QP 编码（动作图写入码流）
  -> decoder fresh decode，并仅对 G 连通 ROI 跑 SeedVR2
```

开发集已有第一轮之前生成的统一 QP16 码流和逐像素重建，可作为同一确定性预分析的缓存，
避免无意义地重复编码；路由代码仍重新从原视频和 QP16 重建计算区域特征。汇报时使用当时
记录的 QP16 encode／fresh-decode 时间，加上本轮实际特征与控制器时间，作为编码端额外
开销。正式 spatial-QP 码流字节单独统计，临时 QP16 字节不计入传输码率。

若训练门槛通过，开发验证沿用 v2 已冻结的六项标准：平均 LPIPS 优于 v1 且字节不超过
110%，相对最近均匀 QP 平均改善且至少 4/6 改善，三动作均出现，两项消融平均及至少
4/6 变差，完整时间低于全 Generate，以及 6/6 真实字节和 fresh-decode 精确回归通过。
开发结果只运行一次且不用于回调模型。

## 资源与停止规则

- 全部任务继续只用一张 A800，DCVC-UF 和 SeedVR2 权重冻结；
- 长任务在 tmux 中运行，保留 heartbeat、GPU 采样、墙钟和三块盘空间；
- 正式输出写入 `/root/autodl-fs/DCVC/runs/a800_low_budget_v3_20260918`；
- 不进入多卡训练、codec 微调或 SeedVR2 微调；
- 训练门槛失败则停在训练集；开发判据失败则保留负结果；开发判据通过则停下来申请新的
  独立测试授权。

## 2026-09-18 实际结果

### 训练集门槛通过

固定的 5 折、每折 3 seed 选择在 tmux 中完成。`base-probe-direct` 把平均 oracle
regret 从 `0.115988` 降到 `0.094149`，相对降低 **18.83%**，超过事先规定的 10%；
最差 25% 样本平均 utility 也从 `0.569501` 提高到 `0.601585`。三个直接目标的严格
折外 R² 均有改善：Generate utility 从 0.177 到 0.292，Enhance 收益从 0.502 到
0.685，Enhance 字节从 0.952 到 0.977。因此才按协议训练全量 ensemble，并且只生成
一次六条开发路由。

训练选择用时 431.73 秒，全量训练用时 47.33 秒。冻结路由在 96 个区域中选择 Base 27、
Generate 24、Enhance 45。缓存路径修正后的六条路由与首次运行的特征、预测和动作逐项
一致；共享 LPIPS 模型加载为 1.65 秒，单条编码端 Base 预分析额外时间均值为 0.440 秒
（不含这次共享加载）。

### 开发集门槛未通过

六条 `val/000..005` 的正式 spatial-QP 结果如下；字节均为最终真实落盘码流，临时 Base
流不传输。

| 方法 | 平均字节／17 帧 | LPIPS | 平均完整时间 |
|---|---:|---:|---:|
| 旧低预算 v1 | 10497.5 | 0.463212 | 21.591 秒 |
| Base 预分析 v3 | 10349.0 | 0.470660 | 21.467 秒 |
| v3 关闭 Generate | 11819.5 | 0.486860 | 6.224 秒 |
| v3 关闭 Enhance | 6727.3 | 0.517987 | 21.687 秒 |
| 全画面 Generate | 4786.8 | 0.478122 | 28.248 秒 |

v3 相对逐样本字节最近的均匀 QP，LPIPS 平均降低 `0.052856`，6/6 条都更好；关闭
Generate 或 Enhance 后分别平均变差 `0.016200` 和 `0.047327`，也都是 6/6 条变差。
三种动作、速度、真实字节和 fresh decode 判据均通过。但 v3 在几乎相同的字节下比 v1
平均 **差 0.007448 LPIPS**，只有 2/6 条优于 v1，因此总判定为未通过。11 项固定判据中
只有“平均 LPIPS 优于 v1”失败；没有根据开发结果回调阈值或重跑模型，也不进入新的
独立测试。

服务器重启后首条 SeedVR2 装载是文件存储冷启动：模型加载 46.92 秒、完整管线
60.38 秒。为与既有预热基线公平比较，另做一次只改缓存状态的复核；预热后为 7.96 秒和
21.44 秒，17 帧逐像素完全一致，质量指标完全一致。冷启动原始结果保留在
`cold_start_regression/`，正式均值使用可比的预热计时。正式阶段连同该复核墙钟
1054 秒，监控峰值 22097 MiB，结果目录 `du -sb` 为 310762350 B；结束时三块盘使用率
约 11.30%／16.68%／23.43%。六张固定第 9 帧对照图已人工检查通过。

权威结果为 `formal/low_budget_v3_summary.json`，资源快照为
`final_resource_snapshot.json`，人工可视化记录为 `formal/visual_inspection.json`。这次
负结果说明 Base 预分析确实提供了可泛化信号，却没有比 v1 的区域排序更好；下一步应先
讨论是否做只使用既有训练／开发产物的 v1-v3 路由差异诊断，再决定是否预注册 hybrid
控制器或补充真实空间码率校准标签。`val/012..023` 没有用于本轮选择，`val/024..029`
仍封存。
