# A800 单卡低预算稳定性改进（v2）

## 为什么做这一轮

已有中预算方案已经通过 12 条独立视频的一次性测试；低预算方案虽然平均指标变好，
但只有 5/12 条视频优于逐样本字节最近的均匀 QP，未达到事先规定的 8/12。因此本轮只
解决一个问题：**在不改 DCVC-UF、不改 SeedVR2、也不读取新测试视频的前提下，让低预算
区域选择在不同视频之间更稳定。**

诊断只使用既有训练标签和 `val/000..005` 开发记录。现有控制器对 Enhance 收益和字节
的预测较可靠，但对 Generate 收益的开发集 R² 只有 0.238；低预算路由又总会用满 4 个
Generate tile。训练标签上的离线回放也显示，预测路由与知道真实反事实标签的 oracle
动作平均只一致约 59%。所以本轮优先改“区域相对关系和不确定性”，不改 spatial-QP
码流语法，也不把 fallback 估算字节误称为最终空间码流字节。

## 数据边界

- 训练与选型：只用现有 REDS train `000..239` 的 500 个样本、8000 个区域标签；
- 交叉验证按原始视频序列分组，`int(sequence) % 5` 决定折号，同一视频的两个或三个
  裁剪绝不会同时落入训练折和验证折；
- 最终开发复验：只用已经使用过的 `val/000..005`，而且冻结方案后只跑一次；
- 已消费的 `val/012..023` 不用于选型、调参或汇报 v2 成败；
- `val/024..029` 仍不读取。任何新的独立测试必须先写协议并再次取得用户授权。

## 冻结的候选集合

所有候选仍只读取编码端已有的 RGB／运动统计，不读取 GT、LPIPS 或 teacher 标签作为
部署输入。

1. `raw`：原来的 16 维区域特征、两层 64 宽 MLP，作为同协议基线；
2. `context`：保留 16 维原特征，再加入 13 个内容特征相对当前 4×4 区域均值的差、
   13 个区域内 z-score，以及 6 个结构／运动特征相对四邻域均值的差，共 48 维；使用
   两层 96 宽 MLP；
3. 每折固定训练 3 个 seed，部署时取均值；这既减少偶然初始化波动，也给出模型分歧；
4. 只对收益做固定的小网格保守校准：Generate 的折外残差 RMSE 系数为
   `{0, 0.25, 0.5, 0.75, 1.0}`，Enhance 为 `{0, 0.25, 0.5}`。校准量从相应动作的
   预测收益中扣除，其他目标和原预算求解器不变；
5. 低预算固定为 Enhance fallback 预测总字节的 0.25、Generate 最多 4 tile；风险权重、
   fragment guard 和三种动作定义沿用 v1。

这里的上下文特征不增加 decoder side information：编码器先从完整待编码视频得到 16 个
区域的原特征，然后在这 16 个数之间做减均值、标准化和邻域差。最终仍只需要把选出的
16 格动作图写进 spatial-QP 码流。

## 训练集内的选择规则

先得到每个训练区域严格折外的预测，再按每个 16 区域样本回放低预算求解器。真实 utility
沿用 v1 的目标：LPIPS 收益减去时序风险、PSNR 风险和 Generate 计算成本；oracle 只用于
离线衡量遗憾，不是部署输入。

候选按以下固定顺序排序：

1. 最小化 500 个样本的平均 oracle regret；
2. 若相差小于 `1e-6`，优先最坏 25% 样本平均 utility 更高者；
3. 再相同则优先保守系数更小、模型更简单者。

只有当最佳 `context` 候选相对最佳 `raw` 候选把平均 regret 降低至少 10%，且最坏 25%
utility 不降低，才允许训练全量 checkpoint 并进入开发集完整编解码。否则把本轮记为训练集
内负结果，不消耗新的 GPU 正式复验。

## 一次性开发复验标准

通过训练集门槛后，在全部 500 个训练样本上用同样的 3 个 seed 训练 ensemble，固定校准
系数，然后只对 `val/000..005` 生成一次新低预算路由。正式结果必须重新空间编码、核对
真实落盘字节、在无源 RGB 的独立进程 fresh decode，并生成固定第 9 帧可视化。

本轮判为“值得进入新独立测试”需要同时满足：

1. 六条平均 LPIPS 优于 v1 低预算，且 v2 实际字节不超过 v1 的 110%；
2. 相对逐样本真实字节最近的既有均匀 QP，平均 LPIPS 改善为正且至少 4/6 条改善；
3. 六条合计仍实际使用 Base、Generate、Enhance 三种动作；
4. 同路由关闭 Generate、关闭 Enhance 的平均 LPIPS 都变差，且各至少 4/6 条变差；
5. 平均完整时间低于既有全画面 Generate；
6. 6/6 码流通过真实字节、原子完成标志和 fresh-decode 逐像素一致性检查。

开发复验无论成功或失败都不据此改系数重跑。成功时停下来申请新的独立数据授权；失败时
保留负结果，再讨论是否需要新增“真实空间码率校准标签”或改变研究假设。两种情况都不
进入多卡训练、DCVC-UF 微调或 SeedVR2 微调。

## 运行与落盘

- 长任务一律在 tmux 中执行，保留逐行日志、60 秒 heartbeat、GPU 峰值和墙钟时间；
- 正式目录固定为 `/root/autodl-fs/DCVC/runs/a800_low_budget_v2_20260918`；
- 中间 checkpoint 可放正式目录；临时帧和可重建缓存放 `/root/autodl-tmp/DCVC/tmp`；
- 结束时记录 `/root`、`/root/autodl-tmp`、`/root/autodl-fs` 三处空间；
- 大文件、数据、码流、PNG 和 checkpoint 不进入 Git。

## 2026-09-18 实际结果：训练集门槛未通过

本轮按上面的固定协议在 tmux 中完成了 5 折、每折 3 seed 的训练集交叉验证。开发集
`val/000..005` 没有进入模型选择，也没有启动完整编解码；`val/012..023` 和
`val/024..029` 均未读取。

- 原 16 维模型的平均 oracle regret 为 `0.114373`，最坏 25% 样本平均 utility 为
  `0.565309`；
- 48 维上下文模型的对应数字为 `0.113667` 和 `0.585797`；
- 上下文使最差四分之一更好，也把误选负收益 Generate 的比例从 13.75% 降至 9.34%，
  但平均 regret 只降低 **0.62%**，没有达到事先规定的 10%；
- Generate LPIPS 收益的严格折外 R² 反而从 0.209 降到 0.195，说明训练误差降低主要是
  过拟合，不能据此进入开发集。

因此程序自动写出 `TRAINING_ONLY_GATE_FAILED` 并停止，没有训练全量 checkpoint、没有
生成开发路由，更没有为了得到好看结果降低门槛。正式选择用时 403.65 秒，监控到的峰值
显存仅 539 MiB；结果目录普通文件约 1.23 MB。权威记录为
`selection/selection_summary.json` 和 `training_only_negative_snapshot.json`。

这个负结果缩小了问题范围：仅加入同画面相对特征不足以可靠预测 Generate 收益。下一步
应测试一个仍可部署的、更直接的信息源——编码端先做一次统一 Base 质量的快速分析，利用
原视频与 Base 重建之间的局部失真来判断哪里值得 Generate／Enhance。编码端本来就拥有
原视频，这不是在 decoder 偷看 GT；但必须单独计入这次预分析的编码开销，并继续用训练
视频分组交叉验证先过门槛。该有界协议见
[`CLOUD_A800_LOW_BUDGET_V3.md`](CLOUD_A800_LOW_BUDGET_V3.md)。
