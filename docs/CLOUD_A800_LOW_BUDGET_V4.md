# A800 单卡低预算融合控制器（v4）

## 这一轮要回答什么

v1 在六条开发视频上最好，但低预算独立测试只有 5/12 条优于最近的均匀 QP；v2 的
同画面上下文减少了有害 Generate，v3 的 Base 预分析明显改善了训练折外预测，但二者
单独使用都没有形成更好的完整控制器。因此 v4 不再要求三选一，而是把它们分工组合：

- v1 是默认判断；
- v2 描述一个区域相对整帧和邻居是否特殊；
- v3 描述一次临时 Base 编解码到底把哪里压坏；
- 新模型只学习何时、以及多大程度上修正 v1。

本轮不再设置“改善至少 10% 才继续”之类的硬门槛。所有候选用同一训练协议比较，选择
综合证据最合适的一个进入既有开发集。门槛改为选择依据，不再是一票否决。

## 数据与模型边界

- 训练与选择只使用既有 REDS train `000..239` 的 500 个 teacher 样本；
- 交叉验证继续按 `int(sequence) % 5` 分组，同一原视频绝不跨训练折和验证折；
- 只把最终选中的一个候选用于既有 `val/000..005` 开发闭环；
- 已消费的 `val/012..023` 不参与选择、调参或 v4 成败判断；
- `val/024..029` 继续封存，不解压、不读取；
- DCVC-UF 和 SeedVR2 始终冻结，只训练几千参数级控制器；
- 全部任务仍只使用一张 A800，不进入多卡或模型／codec 微调。

## 特征怎样组合

每个 4×4 区域先保留 v1 的 16 个颜色、纹理、运动、位置特征。v2 上下文继续加入：

- 相对当前整帧 16 区域均值的差；
- 当前帧内 z-score；
- 相对上下左右邻居的纹理和运动差。

需要 Base probe 的候选还加入 QP16 临时编解码得到的局部 LPIPS、PSNR、RGB MSE 和
时序差，并同时计算它们相对整帧和相邻区域的差。编码器拥有原视频，因此这些量可部署；
临时 Base 流只在编码端使用，不传给解码端。

## 锚定式纠错，而不是重新推翻 v1

v4 先由 v1 预测原来的 8 个中间量，再转换为 Generate utility、Enhance 收益和 Enhance
成本。轻量纠错网络只预测这三项相对 v1 的残差：

```text
v4 预测 = v1 预测 + 纠错比例 × 上下文／Base-probe 纠错
```

比较四类候选：

1. `v1`：不做纠错；
2. `context-residual`：只用 v2 同画面上下文纠错；
3. `probe-residual`：只用 v3 Base 预分析纠错；
4. `hybrid-residual`：同时用 v2 上下文和 v3 Base 预分析纠错。

纠错网络对三项目标使用独立小塔，避免容易预测的字节成本压过 Generate 排序。每折固定
3 个 seed，部署取均值；纠错比例只比较 `{0.25, 0.5, 0.75, 1.0}`。比例为 0 的原 v1
单独作为基线，不会因为重复出现在多个候选中而获得额外选择机会。

## 怎样选择，不设硬门槛

每个候选都用严格折外预测回放低预算求解器。选择顺序为：

1. 平均 oracle regret 更低；
2. 数值几乎相同时，最差 25% 样本的真实 utility 更高；
3. 再相同时，有害 Generate 更少；
4. 仍相同时，纠错更小、结构更简单。

这里没有“必须改善多少才通过”。即使最后还是 v1 最合适，也会如实选择 v1；若融合候选
更合适，则训练全量 checkpoint。选择完成后只运行一个开发候选，避免用六条开发视频在
多个模型之间反复挑选。

## 开发闭环怎样比较

开发集继续报告而不做一票否决：

- 最终 spatial-QP 真实落盘字节和 LPIPS；
- 相对 v1、最近均匀 QP 和全 Generate 的逐视频变化；
- Base／Generate／Enhance 实际动作数量；
- 固定路由关闭 Generate、关闭 Enhance 的两项消融；
- 完整 fresh decode、逐像素一致性、完整时间和峰值显存；
- Base 预分析的编码端额外时间；
- 固定第 9 帧可视化。

最终选择看质量、码率、跨视频稳定性和计算的整体折中，不因单个预设数字自动停止。
开发结果无论正负都不回调训练候选或阈值。若之后需要打开封存数据，仍必须先形成一个
冻结版本并取得用户确认。

## 运行与落盘

- 正式目录：`/root/autodl-fs/DCVC/runs/a800_low_budget_v4_20260918`；
- 长任务在 tmux 中运行，每分钟记录进度、GPU 和三块盘空间；

## 2026-09-18 实测结果

训练集内共比较 117 个候选。最终自动选中 `hybrid-residual`：保留 v1 判断，并同时用
v2 上下文和 v3 Base 预分析做完整强度的残差纠错。这个选择完全由 500 个训练样本的
分组折外结果决定，在选择冻结前没有查看六条开发视频。

| 训练折外候选 | 平均 oracle regret | 最差 25% utility | 有害 Generate |
|---|---:|---:|---:|
| v1 锚点 | 0.113505 | 0.576159 | 11.10% |
| 只用 v2 上下文纠错 | 0.108736 | 0.575622 | 12.49% |
| 只用 v3 Base 预分析纠错 | 0.095818 | 0.596378 | 11.03% |
| v2 + v3 融合纠错 | **0.093707** | **0.613175** | **8.27%** |

融合候选相对 v1 把训练折外 regret 降低 17.44%，最差四分之一 utility 提高 6.42%，
有害 Generate 绝对减少 2.83 个百分点。这说明 v2 的相对上下文不是无用信息：它单独
改写路由时较弱，但与 Base 预分析共同作为“纠错证据”时，训练折外结果最好。

冻结该候选后，只在既有 REDS `val/000..005` 开发集运行一次完整闭环：

| 方法 | 平均真实字节/17帧 | LPIPS | 平均完整解码秒 |
|---|---:|---:|---:|
| 最近均匀 QP（逐样本选择，仅用于比较） | 不同 | 0.512210 | 不同 |
| 全 Generate | 4786.8 | 0.478122 | 28.248 |
| 低预算 v1 | **10497.5** | **0.463212** | **21.591** |
| 融合 v4 | 10594.2 | 0.468980 | 23.263 |
| v4 关闭 Generate | 11918.2 | 0.485538 | 6.199 |
| v4 关闭 Enhance | 6877.8 | 0.515810 | 22.166 |

v4 相对 v1 平均多 96.7 B（0.92%），LPIPS 平均差 0.005769，只有 2/6 条视频质量更好。
它相对逐样本字节最近的均匀 QP 平均改善 0.043230 LPIPS，但只有 5/6 条方向一致，仍弱于
v1 已有的 6/6 稳定性。关闭 Generate 或 Enhance 后，六条视频全部变差，平均分别变差
0.016557 和 0.046830；因此两条分支都有真实贡献，问题在于区域之间的排序还不够稳定，
不是某条分支完全无效。

v4 的动作总数为 Base 26、Generate 24、Enhance 46。编码端临时 QP16 Base 预分析平均
额外约 0.254 秒；临时流平均 8041.3 B，但不传输、不计入最终码率。v4 完整解码比全
Generate 平均快 17.65%，6/6 条都更快；不过比 v1 平均慢 7.75%。

## 综合选择与下一步

本轮没有硬性通过／失败门槛，但仍需要从全部证据中选择一个最合适的版本。当前选择是：

- **低预算主版本继续使用 v1**。它在几乎相同码率下质量更好，而且跨六条视频更稳定；
- v2 上下文和 v3 Base 预分析保留为有价值的辅助信号与论文分析，不把本次 v4 当成失败后
  丢弃；
- v4 不进入新的独立测试，也不因为训练折外漂亮就覆盖实际开发结果；
- 下一轮若继续改进，应做“保守纠错”：只有辅助证据非常一致时才覆盖 v1，并重点检查
  训练裁剪 teacher utility 与完整视频最终 LPIPS 之间的分布错位。仍可在单张 A800 上完成，
  没有理由启动多卡或微调大模型／codec；
- 在出现一个开发集上整体优于 v1 的冻结候选之前，不建议打开 `val/024..029`。若以后确需
  使用这批封存数据，必须先写一次性协议并取得用户确认。
